    Assignment 2

    Conceptual Response

    My studio project is an interactive web-based tool designed for the creative context of UI prototyping and interaction design. It explores how button interactions can become more expressive through the combined use of two core interaction design principles: feedback and mapping.

    The tool centres around a large interactive button surrounded by a series of smaller controls. Each smaller button represents a specific feedback behaviour—such as shake, scale, rotate, glow, or colour change—and can be previewed individually. Checkboxes allow users to select one or more effects, which are then mapped directly to the central button when it is pressed. This creates a clear relationship between user input, system state, and visual output.

    Feedback is the primary focus of the project. Rather than limiting feedback to a single predefined response, the prototype allows multiple forms of visual and motion-based feedback to be layered together. This helps users observe how different combinations affect the perceived responsiveness, personality, and clarity of an interface.

    Mapping plays an equally important role. The radial layout establishes a strong spatial relationship between the surrounding controls and the central button. Each control directly corresponds to a specific feedback behaviour, making the system easy to understand and explore. The interface visually communicates cause and effect: selecting an option changes the behaviour of the central button in a predictable way.

    The novelty of the project lies in turning interface feedback into something modular, interactive, and user-configurable. Instead of passively experiencing feedback, users actively construct it.

    Technical Approach

    My project was built using HTML, CSS, and JavaScript. HTML provides the basic structure, including the central button, the smaller preview buttons, and the checkboxes used for selecting different feedback effects. CSS controls the overall layout, visual style, and animations, while JavaScript manages all user interactions and dynamic behaviour.

    The main technical challenge was creating a system where multiple feedback effects could be selected and combined. To solve this, I used JavaScript event listeners to detect button clicks and checkbox selections. Each effect is stored using custom data attributes, which makes the code more flexible and easier to expand. When the central button is pressed, JavaScript checks which options are active and applies the corresponding visual changes.

    CSS custom properties were used to control transformations such as movement, scaling, rotation, and colour changes. This made it possible to update the button's appearance dynamically through JavaScript without rewriting the entire style. Additional visual effects, such as glow, were handled using CSS classes.

    The smaller buttons also work as live previews. Each one triggers its own animation, helping users understand the effect before applying it to the main button.

    Peer User Testing Reflection

    Link to Peer user testing form

    Peer testing revealed several valuable insights about the current prototype. While most participants found the interface engaging and easy to explore, a common issue was the relationship between the small buttons, checkboxes, and the central button. Some users understood the interaction immediately, but others were unsure how the system worked at first. In particular, several participants did not realise that selecting a checkbox required them to then click the central button to trigger the combined effects. This suggests that the current mapping between input and outcome is not yet fully intuitive.

    This feedback highlighted an important tension in the design. I initially aimed to minimise textual instructions in order to create a more playful and immersive experience. However, the testing showed that removing too much guidance can make the interaction less discoverable. Moving forward, I plan to introduce subtle instructional cues and clearer visual affordances while still maintaining a clean and exploratory interface.

    One significant change I intend to implement is replacing the checkbox selection system with a drag-and-drop interaction. Users will be able to drag the smaller feedback buttons directly onto the central button to apply their effects. This will create a much stronger sense of mapping, making the relationship between controls and output immediately understandable. It also aligns more naturally with the experimental and playful nature of the project.

    Participants also suggested expanding the range of available feedback. Many wanted audio feedback, adjustable effect intensity, and greater control over colours and animation strength. Others expressed interest in having multiple variations within each feedback category. In response, I plan to introduce additional effects, parameter controls, and customisation options to support deeper experimentation.

    Overall, peer testing confirmed the strengths of the current concept while clearly identifying opportunities for improvement. The next iteration will focus on improving discoverability, strengthening mapping through drag-and-drop interaction, and expanding the expressive possibilities of the feedback system.

    Assignment 4: Reflection

    Introduction

    My final project, Feedback Builder, changed significantly throughout the design and development process. While the project remained focused on the interaction design principles of feedback and mapping, its purpose evolved as I learned more about how users interacted with the prototype and what they found interesting.

    The final project became an interactive tool that allows users to experiment with combining multiple feedback effects, adjusting their intensity, and generating reusable CSS code. Looking back, I believe this evolution improved the project by making it both a learning tool and a practical creative tool.

    Was the Project Successful? What Did I Learn?

    I believe Feedback Builder was successful in achieving its final purpose. The project is simple to use and focuses on a very specific area of interaction design: button feedback.

    Unlike many CSS generator websites that provide a large number of different CSS properties, Feedback Builder only focuses on creating and combining feedback effects for a single button. This narrow scope makes the experience more straightforward and easier to understand.

    The project also evolved beyond my original idea. Instead of only observing different levels of feedback, users can now create their own feedback combinations, adjust their intensity, and generate reusable CSS code.

    One important lesson I learned was that simplicity and clarity are not always the same thing. At the beginning, I intentionally reduced instructions because I wanted users to discover the interaction naturally.

    However, peer testing showed that too little guidance could make the interaction difficult to understand. This taught me that successful interaction design often requires a balance between exploration and guidance.

    I also learned that creating a customisable interaction system is much more complex than creating individual interactions. While each feedback effect worked well on its own, combining multiple effects introduced many technical conflicts and design challenges.

    Resolving conflicts between shake, scale, rotate, glow, and wave effects helped me better understand the relationship between interaction design and technical implementation.

    How the Final Design Meets My Initial Judgement of Purpose

    My initial purpose was to explore different degrees of feedback and observe how users react to them. I wanted users to notice how feedback influences confidence and how quickly they realise their actions have been recognised by the system.

    Although the final design is quite different from the original concept, it still achieves the same underlying goal. Users are still exploring feedback, but now they actively create and combine feedback effects rather than simply observing them.

    The project also continues to explore mapping. The relationship between the outer buttons and the central button became a key part of the final interaction design, helping users understand how interface elements influence each other.

    How My Initial Judgement of Worth Is Reflected in the Final Design

    At the beginning of the project, I believed the value of the project was demonstrating the importance of feedback and helping users understand that both too little and too much feedback can negatively affect interaction.

    This value remains present in the final project. Users can experiment with subtle effects, strong effects, and combinations of multiple effects to discover what feels effective or distracting.

    The project also developed an additional value that was not part of the original plan: creative expression. Through sliders, colour pickers, and effect combinations, users can create feedback styles that reflect their own preferences.

    The CSS export system strengthened this value further by allowing users to reuse their creations in future projects.

    Novel Application of Feedback and Mapping

    Most interfaces use feedback as a supporting element that confirms actions or communicates system status. In Feedback Builder, feedback itself became the primary focus of the interaction.

    Users interact with the system specifically to explore and create feedback combinations. This shifts feedback from a supporting role into the main experience.

    Mapping was explored through the relationship between the outer buttons and the central button. The introduction of drag-and-drop interactions created a clearer and more physical connection between these elements.

    Design Judgements Through Exploration

    Design Judgement 1 — Guiding interface

    One design challenge throughout this project was deciding how much guidance should be provided to users. Because Feedback Builder focuses on exploration and experimentation, I wanted users to spend most of their attention on interacting with feedback effects rather than reading instructions.

    To explore this problem, I created three different guidance designs and compared their strengths and weaknesses.

    The first design placed instructional text directly beside the buttons. This approach was very straightforward and immediately explained how the interface worked. However, it also introduced a large amount of visible text onto the screen.

    While this version improved learnability, it made the interface feel more cluttered and less aligned with my original goal of creating a simple and focused interaction space.

    The second design introduced a dedicated guide button. When pressed, a pop-up window would appear containing instructions about how the system works.

    I found this approach more successful because the guide itself used the same interaction method as the rest of the project: clicking a button. This created a more consistent experience and allowed users to access guidance only when needed.

    This design also preserved the visual simplicity of the interface while still supporting users who required additional information. For these reasons, this became the version I selected for the final project.

    The third design displayed a guidance pop-up automatically when the website first loaded. Users could dismiss it by clicking anywhere on the screen.

    Although this approach guaranteed that every user would see the instructions, it prevented users from immediately seeing the main interaction area. Since I wanted the feedback experimentation space to be the primary focus of the project, I felt this approach created an unnecessary barrier between the user and the core experience.

    Through exploring these three alternatives, I learned that guidance should support interaction without dominating it. The final solution balanced learnability with simplicity while remaining consistent with the overall interaction design of the project.

    Design Judgement 2 — Button shape

    Another design judgement involved the shape of both the central button and the surrounding effect buttons. Because Feedback Builder relies heavily on interaction, I wanted the button shapes to clearly communicate which element users should focus on and interact with.

    To explore this, I created three different button shape variations and compared how they affected usability, mapping, and visual hierarchy.

    The first design used rectangular outer buttons together with a rectangular central button. This version ultimately became the final design.

    I found that rectangular buttons felt the most familiar and intuitive because they closely resemble common button designs found in websites, applications, and operating systems. Users could immediately recognise them as interactive elements without needing additional explanation.

    The rectangular shapes also provided more space for effect names such as "Shake", "Glow", and "Rotate", making labels easier to read and helping users understand the available feedback options.

    Most importantly, this version created the clearest visual hierarchy. The larger centre button naturally appeared as the primary interaction target, while the surrounding buttons were clearly understood as supporting controls.

    The second design combined rectangular outer buttons with a circular central button. The intention was to make the centre button stand out more strongly as the main interaction area.

    While the circular button successfully attracted attention, I found that it introduced a visual inconsistency between interface elements. The central button appeared to belong to a different interaction system than the surrounding controls.

    This weakened the relationship between the outer buttons and the central button, making the overall mapping feel slightly less cohesive. Since the project relies on users understanding the connection between these elements, maintaining consistency became more important than emphasising the centre button alone.

    The third design used circular buttons for both the centre button and the surrounding effect buttons. This version created a more playful and visually balanced appearance.

    However, it also introduced several usability issues. The circular outer buttons provided less space for text labels, making some effect names harder to read and requiring more careful layout adjustments.

    In addition, because every button shared a similar shape, the visual hierarchy became weaker. The centre button no longer stood out as clearly as it did in the first design, making it slightly harder for users to immediately identify the primary interaction target.

    After comparing all three versions, I selected the first design because it offered the strongest balance between usability, readability, consistency, and visual hierarchy. While the other options were visually interesting, the rectangular layout supported the interaction goals of the project more effectively.

    This exploration reinforced an important lesson: even small visual decisions, such as button shape, can significantly influence how users understand interaction relationships and navigate an interface.

    Production Timeline and Project Development

    My original timeline focused on improving visual guidance, redesigning the interaction flow, expanding the feedback library, and introducing customisation features.

    Some decisions changed throughout development. For example, I originally planned to introduce sound feedback, but later decided to focus entirely on visual feedback to maintain consistency.

    Some features took less time than expected, such as implementing effect intensity sliders. However, the CSS export system became one of the most technically demanding features in the project.

    Resolving conflicts between multiple feedback effects also required much more time than originally expected.

    Aspect of Design I Am Most Proud Of

    The aspect of the project I am most proud of is the feedback combination system and CSS export functionality.

    The combination system successfully transformed feedback from something users simply observe into something they can actively create and customise.

    The CSS export feature further extended the usefulness of the project by allowing users to reuse their feedback designs outside the tool itself.

    Aspect of Design I Found Most Challenging

    The most challenging aspect of the project was managing conflicts between multiple feedback effects.

    Since many effects relied on similar CSS properties, combining them often created unexpected behaviour and technical issues.

    The CSS export system was also challenging because I needed to determine which code should be exported and how the generated code could remain reusable in other projects.

    Reflection on a Peer's Creative Tool

    One peer project that provided an insightful contrast to my own was A Bard's Tale.

    While Feedback Builder focuses on minimalism, experimentation, and user-created interactions, A Bard's Tale focuses on immersion, storytelling, and guided experiences.

    Experiencing this project helped me recognise that meaningful interaction design does not always require simplicity. Rich visual design, character animation, and narrative elements can also create highly engaging experiences.

    This contrast helped me better understand my own design decisions and the different ways interaction design can create engagement.
