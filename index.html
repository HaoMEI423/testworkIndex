    Assignment 2

    Conceptual Response

    My studio project is an interactive web-based tool designed for the creative context of UI prototyping and interaction design. It explores how button interactions can become more expressive through the combined use of two core interaction design principles: feedback and mapping.

    The tool centres around a large interactive button surrounded by a series of smaller controls. Each smaller button represents a specific feedback behaviour—such as shake, scale, rotate, glow, or colour change—and can be previewed individually. Checkboxes allow users to select one or more effects, which are then mapped directly to the central button when it is pressed. This creates a clear relationship between user input, system state, and visual output.

    Feedback is the primary focus of the project. Rather than limiting feedback to a single predefined response, the prototype allows multiple forms of visual and motion-based feedback to be layered together. This helps users observe how different combinations affect the perceived responsiveness, personality, and clarity of an interface.

    Mapping plays an equally important role. The radial layout establishes a strong spatial relationship between the surrounding controls and the central button. Each control directly corresponds to a specific feedback behaviour, making the system easy to understand and explore. The interface visually communicates cause and effect: selecting an option changes the behaviour of the central button in a predictable way.

    The novelty of the project lies in turning interface feedback into something modular, interactive, and user-configurable. Instead of passively experiencing feedback, users actively construct it.

    Technical Approach

    My project was built using HTML, CSS, and JavaScript. HTML provides the basic structure, including the central button, the smaller preview buttons, and the checkboxes used for selecting different feedback effects. CSS controls the overall layout, visual style, and animations, while JavaScript manages all user interactions and dynamic behaviour.

    The main technical challenge was creating a system where multiple feedback effects could be selected and combined. To solve this, I used JavaScript event listeners to detect button clicks and checkbox selections. Each effect is stored using custom data attributes, which makes the code more flexible and easier to expand. When the central button is pressed, JavaScript checks which options are active and applies the corresponding visual changes.

    CSS custom properties were used to control transformations such as movement, scaling, rotation, and colour changes. This made it possible to update the button's appearance dynamically through JavaScript without rewriting the entire style. Additional visual effects, such as glow, were handled using CSS classes.

    The smaller buttons also work as live previews. Each one triggers its own animation, helping users understand the effect before applying it to the main button.

    Peer User Testing Reflection

    Link to Peer user testing form

    Peer testing revealed several valuable insights about the current prototype. While most participants found the interface engaging and easy to explore, a common issue was the relationship between the small buttons, checkboxes, and the central button. Some users understood the interaction immediately, but others were unsure how the system worked at first. In particular, several participants did not realise that selecting a checkbox required them to then click the central button to trigger the combined effects. This suggests that the current mapping between input and outcome is not yet fully intuitive.

    This feedback highlighted an important tension in the design. I initially aimed to minimise textual instructions in order to create a more playful and immersive experience. However, the testing showed that removing too much guidance can make the interaction less discoverable. Moving forward, I plan to introduce subtle instructional cues and clearer visual affordances while still maintaining a clean and exploratory interface.

    One significant change I intend to implement is replacing the checkbox selection system with a drag-and-drop interaction. Users will be able to drag the smaller feedback buttons directly onto the central button to apply their effects. This will create a much stronger sense of mapping, making the relationship between controls and output immediately understandable. It also aligns more naturally with the experimental and playful nature of the project.

    Participants also suggested expanding the range of available feedback. Many wanted audio feedback, adjustable effect intensity, and greater control over colours and animation strength. Others expressed interest in having multiple variations within each feedback category. In response, I plan to introduce additional effects, parameter controls, and customisation options to support deeper experimentation.

    Overall, peer testing confirmed the strengths of the current concept while clearly identifying opportunities for improvement. The next iteration will focus on improving discoverability, strengthening mapping through drag-and-drop interaction, and expanding the expressive possibilities of the feedback system.

    Assignment 4: Reflection

    Was the Project Successful? What Did I Learn?

    I believe Feedback Builder was successful in achieving its final purpose. The project is simple to use and focuses on a very specific area of interaction design: button feedback.

    Unlike many CSS generator websites that provide a large number of different CSS properties, Feedback Builder only focuses on creating and combining feedback effects for a single button. This narrow scope makes the experience more straightforward and easier to understand.

    The project also evolved beyond my original idea. Instead of only observing different levels of feedback, users can now create their own feedback combinations, adjust their intensity, and generate reusable CSS code.

    Through user testing and presentations, I found that most users could understand the core interaction quickly and enjoyed experimenting with different feedback combinations.

    One of the most important things I learned was that simplicity and clarity are not always the same thing. At the beginning, I tried to minimise instructions because I wanted users to discover the interaction naturally.

    However, peer testing showed that reducing information too much can make interactions difficult to understand. This taught me that learnability often requires a balance between exploration and guidance.

    I also learned that design decisions are rarely fixed. Many features changed throughout development, including drag-and-drop interaction, effect intensity sliders, colour customisation, and the CSS export system.

    These changes taught me that design is an iterative process. Testing ideas, finding problems, and improving solutions became an important part of the project.

    Another important lesson was understanding the relationship between design and technical implementation. Creating individual feedback effects was relatively straightforward, but combining multiple effects introduced unexpected technical conflicts.

    Resolving issues between shake, scale, rotate, glow, and wave effects required both design thinking and technical problem solving. This helped me better understand how interaction design decisions can directly influence coding complexity.

    Finally, this project changed the way I think about feedback. Before this project, I mainly viewed feedback as a way to confirm user actions. Through designing and building Feedback Builder, I began to see feedback as something that can communicate emotion, personality, and expression within an interface.
